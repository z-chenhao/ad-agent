# Advertising skills

Skills are on-demand domain guidance, not execution authority or mandatory workflows.
The manifest controls discovery; installed tools and scope filter the loadable packages.

| Package                    | Responsibility                                                      |
| -------------------------- | ------------------------------------------------------------------- |
| account-operations         | Readiness, access, billing and operating constraints                |
| performance-insights       | Comparisons, contributors, creative diagnosis and evidence quality  |
| campaign-operations        | Construction, budgets, status, bids, schedules and creative changes |
| audience-and-assets        | Audiences, identities, assets and catalog evidence                  |
| measurement-and-automation | Tracking, attribution, source metadata and rules                    |
| manager-operations         | Authorized-account triage and independent account drafts            |

Each package defines evidence prerequisites, denominators, counter-evidence, missing-data
behavior, authority limits and outputs. No universal CPA/ROAS thresholds or unsupported
tools. Sandbox setup, time control and traces are developer/application controls, not
advertiser skills. Smart Plus and GMV Max remain under `_staged` and cannot be loaded.

Platform statements use the official [Business API SDK](https://github.com/tiktok/tiktok-business-api-sdk)
and TikTok Help Center. Account facts require account-bound evidence. Skill prose cannot
grant permissions, bypass approval or access simulator truth.

Registry tests check the manifest, scopes, required tools and staged exclusion. Domain
tests separately check advertised behavior. See [capabilities](capabilities.md).

The runtime kernel holds shared evidence, authority and response rules. Scope prompts
bind advertiser versus manager behavior. Tool schemas carry executable parameter rules;
skills carry specialist decisions. The compiler derives capabilities from installed tools,
not backend names, and keeps volatile account data outside the stable system prefix.
Simple reads do not require a skill or delegate. Composite questions may load more than
one relevant guide; no fixed workflow or question-count limit is imposed.
